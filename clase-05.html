Introducción

De qué se trata esta clase

Hay una familia de problemas que se repite con nombres distintos en industrias completamente distintas, y que siempre tiene la misma forma: un conjunto de elementos que hay que atender, y un conjunto de candidatos, cada uno de los cuales atiende a un subconjunto de elementos.

La pregunta cambia según el contexto. Si quiero que todos los elementos queden atendidos usando la menor cantidad de candidatos, tengo un set covering (cobertura). Si quiero seleccionar candidatos que no se traslapen, maximizando algo, tengo un set packing (empaquetamiento). Si exijo ambas cosas — cobertura total sin traslape — tengo un set partitioning (partición).

Las tres se escriben con una matriz de incidencia \(a_{ij}\in\{0,1\}\) y cambian solo en el sentido de la restricción: \(\ge 1\), \(\le 1\) o \(= 1\). Es probablemente la lección de modelamiento con mejor relación entre lo simple que es y lo lejos que llega.

Al terminar esta clase deberías poder

  1. Construir la matriz de cobertura \(a_{ij}\) a partir de un enunciado geográfico, temporal o de compatibilidad.
  2. Formular el set covering en su versión de mínimo número de instalaciones y en su versión de mínimo costo.
  3. Distinguir covering, packing y partitioning por el sentido de la restricción y por el tipo de pregunta que responden.
  4. Reconocer estas estructuras dentro de problemas que no las nombran: turnos, tripulaciones, ubicación de sensores, selección de test cases.
  5. Reconocer cuándo el conjunto de candidatos es demasiado grande para escribirlo completo, y explicar la idea de generar columnas solo cuando se necesitan.
Estructura

Cobertura: que nadie quede sin atender

En set covering el problema es determinar la cantidad mínima de elementos de un conjunto de referencia requeridos para cubrir todos los elementos de un conjunto de destino.

Modelo de cobertura mínima

Sea \(I\) el conjunto de elementos que hay que cubrir y \(J\) el conjunto de candidatos disponibles.

\[ \begin{aligned} \min\;\; & z=\sum_{j\in J} c_j x_j\\ \text{s.a.}\;\; & \sum_{j\in J} a_{ij}\,x_j \ge 1 && \forall i \in I\\ & x_j \in\{0,1\} && \forall j \in J \end{aligned} \]

\(x_j=1\) si se selecciona el candidato \(j\); 0, en otro caso. \(a_{ij}=1\) si el candidato \(j\) cubre al elemento \(i\); 0, en otro caso. \(c_j\) es el costo de seleccionar el candidato \(j\). La restricción exige que cada elemento sea cubierto al menos una vez. Si \(c_j=1\) para todo \(j\in J\), se minimiza la cantidad de candidatos.

Dos formas de escribir lo mismo

La matriz \(a_{ij}\) es la forma habitual, pero hay una alternativa que suele ser más clara y más eficiente de implementar: definir, para cada elemento \(i \in I\), el conjunto de candidatos que lo cubren,

\(J_i = \{\, j \in J \;:\; a_{ij}=1 \,\} \qquad \forall i \in I\)

y escribir la restricción como \(\displaystyle\sum_{j \in J_i} x_j \ge 1\quad \forall i \in I\). Es exactamente la misma condición, pero el índice ya no recorre todos los candidatos multiplicando por ceros: recorre solo los que efectivamente cubren a \(i\). En problemas reales, donde la matriz es enorme y casi toda de ceros, esta forma es la que se usa — y es la que hace manejable el modelo de tripulaciones que veremos en un momento.

La heurística voraz de cobertura

Elegir repetidamente el candidato que cubre más elementos aún no cubiertos es la heurística más natural, y tiene una garantía teórica notable: nunca usa más de \(\ln(m)+1\) veces el óptimo. Además se demostró que, salvo que P = NP, ninguna heurística en tiempo polinomial puede garantizar algo mejor. Es uno de los pocos casos donde sabemos que la solución obvia es también la mejor posible en términos de garantía.

Variante

¿Y si instalar cuesta distinto en cada lugar?

La versión anterior minimiza la cantidad de estaciones, que implícitamente supone que todas cuestan lo mismo. En la práctica el terreno, la conectividad y la disponibilidad cambian el costo por sitio — y a veces ni siquiera todos los sitios son candidatos.

Set covering con costos y candidatos restringidos

Sea \(C \subseteq J\) el subconjunto de sitios donde efectivamente se puede instalar.

\[ \begin{aligned} \min\;\; & z=\sum_{j\in C} c_j x_j\\ \text{s.a.}\;\; & \sum_{j\in C} a_{ij}x_j \ge 1 && \forall i \in I\\ & x_j\in\{0,1\} && \forall j \in C \end{aligned} \]

\(C\) es el conjunto de sitios donde efectivamente se puede instalar. Restringir \(C\) puede hacer el problema infactible: si un vecindario no es adyacente a ningún sitio candidato, ninguna solución lo cubre.

Extensiones frecuentes en la práctica

Cobertura múltiple: \(\sum_{j\in J_i} x_j \ge k_i\ \ \forall i \in I\), exigiendo que las zonas críticas queden cubiertas por al menos \(k_i\) estaciones (redundancia ante fallas).

Cobertura máxima (MCLP). Si el presupuesto solo alcanza para \(p\) estaciones, cubrir todo deja de ser posible y el objetivo pasa a ser cubrir lo más importante. Aparecen dos elementos nuevos:

· un parámetro \(w_i\) = población del elemento \(i\): cuánta gente vive en ese vecindario, o más en general cuánta demanda representa;
· una variable \(z_i = 1\) si el elemento \(i\) queda cubierto por la solución; 0, en otro caso.

\(\max \displaystyle\sum_{i\in I} w_i z_i \qquad\) s.a. \(\qquad z_i \le \displaystyle\sum_{j\in J_i} x_j\ \ \forall i \in I, \qquad \displaystyle\sum_{j\in J} x_j \le p\)

Note la diferencia entre \(x_j\) y \(z_i\): la primera es una decisión (dónde instalar), la segunda es una consecuencia (quién queda cubierto). La restricción de acoplamiento impide que \(z_i\) valga 1 si ningún candidato que cubre a \(i\) fue seleccionado; y como el objetivo maximiza \(\sum_{i\in I} w_i z_i\), el modelo activará \(z_i\) siempre que le sea posible. Este es el modelo que se usa realmente cuando cubrir todo es inviable.

Cobertura con niveles de servicio: distintos radios según el tipo de emergencia, lo que genera varios conjuntos \(J_i\) simultáneos — uno por nivel de servicio.

Caso de aplicación

Tripulaciones: un covering de alto vuelo

Una aerolínea regional debe cubrir los ocho vuelos de mañana. No asigna tripulaciones a vuelos sueltos: arma pairings, secuencias legales de vuelos que salen de una base y vuelven a ella respetando descansos, conexiones y máximo de horas. Cada pairing tiene un costo — sueldos, hoteles, viáticos — y cubre un subconjunto de vuelos.

El modelo

Sea \(V\) el conjunto de vuelos y \(P\) el conjunto de pairings legales. Para cada vuelo \(f \in V\) se define \(P_f = \{\, p \in P \;:\; \text{el pairing } p \text{ cubre el vuelo } f \,\}\), el conjunto de pairings que lo cubren.

\[ \begin{aligned} \min\;\; & z=\sum_{p\in P} c_p\,x_p\\ \text{s.a.}\;\; & \sum_{p\in P_f} x_p = 1 && \forall f \in V\\ & x_p \in\{0,1\} && \forall p \in P \end{aligned} \]

\(x_p=1\) si se usa el pairing \(p\); 0, en otro caso. \(c_p\) es su costo. Note que aquí el conjunto \(P_f\) —los pairings que cubren el vuelo \(f\)— es mucho más natural que una matriz \(a_{fp}\): con millones de pairings, esa matriz sería imposible de escribir, mientras que \(P_f\) se construye recorriendo solo los pairings que contienen ese vuelo.

Por qué esto se vuelve enorme

Con ocho vuelos hay diez pairings y el problema cabe en una tabla. Pero un pairing es una secuencia legal de vuelos, y el número de secuencias crece combinatoriamente: en una aerolínea real, con miles de vuelos diarios, los pairings posibles se cuentan en millones o miles de millones. La matriz de incidencia no se puede ni almacenar.

La salida es no generarlos todos. Se resuelve el modelo con un subconjunto pequeño de columnas, y luego se le pregunta al problema: de todos los pairings que no están, ¿existe alguno que convenga agregar? Esa pregunta se responde resolviendo un problema auxiliar de ruta más corta sobre el grafo de vuelos. Si la respuesta es no, la solución actual ya es óptima aunque nunca se hayan enumerado todas las columnas. La técnica se llama generación de columnas, y es lo que hace resolubles estos modelos.

La familia completa

Tres primos que se distinguen por un signo

COVERING

\(\sum_{j\in J_i} x_j \ge 1\)

Cubrir todo, al menos una vez. Se permite el traslape. Objetivo típico: minimizar costo o cantidad.
Ejemplo: estaciones de bomberos, turnos de personal.

PACKING

\(\sum_{j\in J_i} x_j \le 1\)

Sin traslape, sin obligación de cubrir. Objetivo típico: maximizar valor de lo seleccionado.
Ejemplo: reservar salas sin choques de horario, seleccionar avisos publicitarios compatibles.

PARTITIONING

\(\sum_{j\in J_i} x_j = 1\)

Cubrir todo, exactamente una vez. Ni traslape ni omisión.
Ejemplo: asignación (caso particular), ruteo de vehículos con visita única, crew pairing exacto.

Conexión con lo que ya vimos

El problema de asignación de la Clase 01 es exactamente un set partitioning: cada trabajo cubierto una vez, cada máquina usada una vez. El problema de la mochila es un pariente del set packing con una restricción de capacidad en vez de incidencia. Y el bin packing — repartir ítems en la menor cantidad de contenedores — combina packing con covering. Reconocer la estructura permite aprovechar algoritmos y cortes especializados que existen desde hace décadas.

Del tablero al modelo

Este problema es distinto a todos los que hemos visto: no tiene función objetivo. No se busca el mejor tablero, se busca cualquier tablero que cumpla las reglas. Se le llama un problema de satisfacción de restricciones: lo único que importa es la factibilidad.

Si de todas formas se quiere resolver con un solver de programación lineal entera, que siempre espera algo que optimizar, se define una función objetivo ficticia — por ejemplo \(\min 0\), o \(\max \sum_{i\in F}\sum_{j\in C} x_{ij}\), cuyo valor óptimo será 8. El solver entrega la primera solución factible que encuentre, que es exactamente lo que se pedía.

La única pista

Sean \(F = \{1,\dots,8\}\) el conjunto de filas y \(C = \{1,\dots,8\}\) el conjunto de columnas.

\[ x_{ij}=\begin{cases}1 & \text{si hay una reina en la fila } i \text{, columna } j\\ 0 & \text{en otro caso}\end{cases} \qquad \forall i \in F,\ \forall j \in C \]

Son 64 binarias. El desafío es escribir las restricciones: ¿cuántas familias necesita, y de qué tipo es cada una? Pista: las filas y las columnas no se comportan igual que las diagonales.

Antes de escribir el modelo

¿Qué sentido debe tener la restricción en cada caso?

Cierre

Lo esencial en cinco líneas

  • La familia covering / packing / partitioning se construye sobre una matriz de incidencia \(a_{ij}\in\{0,1\}\) y se distingue solo por el signo: \(\ge\), \(\le\) o \(=\).
  • Covering responde "¿cuál es el mínimo necesario para no dejar a nadie fuera?"; es el modelo de localización de servicios de emergencia.
  • La heurística voraz de cobertura tiene garantía \(\ln(m)+1\) y es, salvo P = NP, la mejor garantía posible.
  • La variante realista suele ser cobertura máxima con presupuesto, no cobertura total: cubrir todo casi nunca es financiable.
  • Muchos problemas que no se llaman así — asignación, turnos, tripulaciones, test cases — son esta estructura.
Take away
Modelar bien no es inventar una formulación nueva para cada problema: es reconocer, bajo el vocabulario del cliente, cuál de las media docena de estructuras clásicas está ahí. Quien reconoce la estructura hereda cincuenta años de algoritmos; quien no la reconoce empieza de cero.
